The base64 blob decodes to 242 bytes of PLAIN TEXT (the marker and a purpose

configuration change. The decoded content is preserved in
evidence/phase7_payload_decoded.txt; its SHA256 is in the manifest.

WHY IT WAS EXECUTED
-------------------
Phase 6 documented a specific coverage limitation of SOC002-DET-001 v2: the
trigger matches an encoded-command CLI switch (-EncodedCommand/-enc/-e/-en), so a
command that instead reconstructs text inside PowerShell with
[Convert]::FromBase64String(...) is not matched. Phase 7 exists to test exactly
that limitation with one benign, documented, reversible action - a true-positive
validation of the detection stack, not a new attack scenario.

HOW IT WAS DELIVERED (OBSERVED)
-------------------------------
The lab administers WS001 over WinRM, and the WinRS client delivers every remote
call as "cmd.exe /C powershell -EncodedCommand <b64>". That transport wrapper is
part of the baseline, not part of the test. Two operational constraints shaped
delivery and neither was worked around by weakening anything:

  * WS001's effective execution policy is Restricted (every scope Undefined), so
    a staged .ps1 cannot be executed there. Phase 7 therefore did NOT use
    -ExecutionPolicy Bypass and did NOT change any policy;
  * a WinRS transport command line is bounded (~8 KB), so a 6 KB collection
    body cannot be sent inline.

The controlled payload was therefore staged as a small text file and handed to a
plainly started powershell.exe via -Command by a one-line WinRM loader:
  $c=[IO.File]::ReadAllText('...\phase7_child_command.txt');
  powershell.exe -NoProfile -NonInteractive -Command $c
That loader line contains no encoded-command switch and no base64-decode literal.

ONE FAILED FIRST ATTEMPT (OBSERVED, benign)
-------------------------------------------
The first attempt invoked a staged runner file with "& '<path>.ps1'". WS001
refused it: "running scripts is disabled on this system" (RC=1). The payload did
NOT execute, no marker was produced, and no child PowerShell process was created
(see the session Sysmon evidence: the only powershell.exe creates belong to the
WinRS transport and to the successful run). No policy was changed in response.
The transcript is preserved in evidence/t3_controlled_execution_ws001.txt.

CONCLUSION
----------
Outcome B. The Phase 6 blind spot is confirmed by direct measurement on the
controlled activity: a PowerShell execution that reconstructs text with
[Convert]::FromBase64String(...) through -Command is invisible to the DET-001 v2
trigger, visible to DET-002 as lineage context, and not correlated by CORR-001.
No detection was modified in Phase 7 to change this result.
